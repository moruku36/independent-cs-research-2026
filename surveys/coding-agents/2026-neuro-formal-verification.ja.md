# Neuro-Formal Verification：エージェントによる言語横断の形式的プログラム推論

## 概要

- **何について**：プログラム推論を検証器で確認できる成果物へ変換するプレプリント。
- **何を述べるか**：ニューラルな翻訳と形式検証を、段階化したパイプラインで組み合わせる。
- **留意点**：翻訳後のモデルが検証できても、元プログラムに対する健全性は保証されない。

## 書誌情報・確認範囲

## 問い・方法・証拠

完全な記号的フロントエンドなしに、一般的な言語のコードについて有用な検証付き推論を得られるか。エージェントが前提を形式化し、コードと性質を翻訳して証明を探索する。DafnyとCBMCを使い、Pythonのプログラム・仕様206組で評価している。主評価はgpt-5.6-sol、5試行・10修復ラウンドを用いる。[N1 §§1–4]

| 報告された結果 | 正しい判定／出した判定 | 再現率の分母 |
|---|---|---|
| Dafny統合パイプライン | 118／128＝適合率92.2% | 118／206＝57.3% |
| CBMCによる反証 | 65／72≒適合率90% | バグあり103件中65件≒63% |

両行の母集団は異なる。適合率の分母に判定保留は入らない。57.3%は正しい判定の再現率であり、判定を出した割合128／206ではない。翻訳や前提の誤りは残る。[N1 Table 3、§§4.2–4.3]

## 批判的考察・妥当性

本サーベイの評価では、「検証器が対象成果物を受理したか」と「その成果物が意図した元コードの振る舞いを忠実に表すか」を分ける必要がある。証明ログは前者を支えても、後者を解決しない。

| 本サーベイの点検案 | 確認する問い |
|---|---|
| 入力範囲 | 空・負数・非整数・例外値を意図どおりに扱っているか |
| 環境モデル | ライブラリのモデルは独立した契約から作られたか |
| 成果物の同一性 | 証明修復中にプログラムや性質が変わっていないか |
| 反例 | 元の言語で反例を再実行できるか |
| 未確定の結果 | タイムアウト・証明失敗を正しさやバグと呼んでいないか |

追加実験の報告ではなく、レビュー項目の提案である。小規模関数のベンチマークから、状態を持つサービス、分散実行、依存関係の多いアプリケーションの信頼性までは推論できない。誤った抽象化が検証器の受理で権威づけされないよう、抽象化そのものを残して点検する。
