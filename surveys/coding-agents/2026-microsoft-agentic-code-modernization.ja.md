# MicrosoftのAIエージェントによる大規模コード移行と仕様駆動開発

- 原題：Cheap code, precious trust: Code modernization at scale
- 著者：Sriram Rajamani、Tim Bozarth（Microsoft）
- 公開日：2026年10月26日
- 原文：[Microsoft Command Line](https://commandline.microsoft.com/agentic-software-engineering-large-scale-code-migration-language-modernization-spec-driven-development/)
- 種別：企業の技術記事。査読済み論文ではない。
- 確認範囲：記事本文を確認。個別の移行結果、ツール実装、証明、再現実験は独立検証していない。

## 7行でつかむ

1. MicrosoftはAIエージェントを使い、WindowsやAzureの大規模コード移行と既存ソフトウェアの近代化に取り組んでいる。
2. C/C++からRustへの移行は、主にメモリ安全性を高めるための取り組みで、既存の動作を保つことが大きな課題。
3. 行ごとに翻訳するより、利用者に見える機能単位で移行し、シナリオテストで確かめる方法が有効だったという。
4. 元と移行先の差分テストや、エージェントに見せないテスト、仕様を使った形式検証で、生成コードを検査する。
5. 大量の同種の修正では、専門家が修正知識を承認し、AIが全体に適用することで人の確認負担を抑える。
6. 結論は、コード生成が速くなるほど、仕様の正しさと検証可能性、人の注意をどこに使うかが重要になるということ。
7. 実務では、小さな機能を対象に既存動作・例外・性能の基準を記録し、差分テストと人の承認から試せる。

## 背景と問い

数億行規模のコードでコンパイラ移行や静的解析の指摘を修正する場合、同種の変更を一貫して適用し、元の動作・セキュリティ・設計意図を維持する必要がある。記事は、コード生成そのものよりも「変更を信頼できると示すこと」と専門家の確認時間が制約になると論じる。

記事のRust移行はメモリ安全性を重視している。性能やサイズの改善は記事で実測・実証されておらず、Rust化しただけで高速化・軽量化すると結論づけられない。

## 手法と報告された状況

### 大規模移行

Windowsの数億行規模のコードへのClang/LLVM対応、CodeQL・PREfast・Roslynの指摘修正、x86からARMへのサービス移行などを例示する。候補事例からAIが修正知識を構築し、レビューエージェントが正確さ・最小性・規約・保守性を確認する。専門家は知識ベースと新規・曖昧なケースを重点的に確認し、エージェントが同種の修正を広く適用する。類似する変更のグループ化も認知負荷を減らす。

### C/C++からRustへ

著者らの報告では、2025年1月は生成コードがコンパイルできず、6月は動作・テストが不十分で、9月には人の支援を受け約3万行の動作する翻訳に至った。2026年2月以降は大規模コードの自動化を進めているという。ただし、対象範囲や評価条件、量的な安全性改善は示されない。

移行は機能単位に分割し、それぞれにエンドツーエンドの検証ゲートを設ける。旧・新実装の差分テストと、エージェントに隠したテストを使う。さらに元コードから形式仕様を抽出し、Rust向け検証器Verusで移行後のコードが仕様を満たすことを証明する取り組みを開始したと述べる。

### 仕様駆動開発

既存コードからAIがTLA+などの仕様を推定し、TLCを使って実装の実行トレースが仕様に許容されるか検査する。不一致はコード、仕様、テストのいずれの問題でもあり得る。小さな有限構成でモデル検査し、F*やLeanで全構成を対象とした証明にも取り組む。人は満たすべき性質を承認し、AIが証明に必要な帰納的不変条件を探す構想である。

実行トレースが仕様に合うことは、仕様が本来の要求を正しく表す保証にはならない。既存コードから作った仕様が既存バグも取り込む可能性を著者ら自身が未解決課題として挙げる。

## 実務への適用案（未実施）

1. **範囲を絞る**：障害時の影響が小さく、入出力を観測できる1機能を選び、現行の仕様・例外・依存関係・戻し方を整理する。
2. **振る舞いを固定する**：正常系・異常系・境界条件のシナリオを用意し、元の実装と新実装の出力を比較する。独立した保留テストも設ける。
3. **性能と安全性を別々に確認する**：レイテンシ、メモリ、CPUなどの目標を事前に決め、同じ条件で実測する。認証・権限・機密情報もレビュー対象にする。
4. **AIへの委任と承認を分ける**：AIには修正案と根拠を生成させ、専門家が移行ルール・仕様・例外とリリース可否を判断する。
5. **段階的に展開する**：CI、段階リリース、監視、ロールバックを準備し、欠陥や想定外の差分を確認してから範囲を広げる。

形式検証は重要な不変条件から導入する選択肢であり、すべてのコードに全面的な証明を求める必要があるという主張ではない。
