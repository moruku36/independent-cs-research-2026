# サブエージェントをメインループへ統合すべき条件

## 概要

- **何について**：エージェント構成の簡素化を扱う実務記事。
- **何を述べるか**：共有文脈・スキル・ツールを中心に、統合の効果を評価する。
- **留意点**：企業での事例は、構成間の普遍的な性能順位を示すものではない。

## 問い・方法・証拠

どの専門家分割がタスク完了を改善するか。S1は企業導入での経験をもとに、必要時に文脈を読み込む方式と共通の端から端までの評価を示す。文脈の隔離、独立した並列作業、ツール・指示の競合が必要な場合はサブエージェントを残し、統合は一境界ずつ比較する。約2倍の速度改善は一顧客の観察で、統制されたベンチマークではない。権限はツールで強制し、手順はスキルに置く。[S1「Using an agent loop」「Task-completion evals」「MCP tools」]

## 批判的考察・妥当性

本サーベイの解釈では、分割の判断単位は依存関係の境界である。同じ証拠を更新しながら往復する計画役・実行役には、統合実験の余地がある。一方、異なる権限を持つ独立検証役は別途評価する必要がある。担当チームの数から構成を決めることはできない。

記事には、効果量を再計算できる共通のワークロード、抽出方法、分散、費用内訳が十分に示されていない。移行方針は仮説として使う。処理の省略でも高速化して見えるため、配送日の取得元を実際に確認したか、といった必須手順を評価に含める。

| 本サーベイの評価案 | 残す証拠 |
|---|---|
| 完了の正しさ | 必須の情報取得と受入条件 |
| 文脈の連続性 | 引き継ぎ時に欠落した事実 |
| 隔離 | 誰が読み取り・書き込み・承認できるか |
| 効率 | 経過時間、トークン、再試行、失敗した実行 |

これは追加の実測結果ではなく、評価設計の提案である。構成の簡素化と同時に権限を広げないことも確認対象になる。
